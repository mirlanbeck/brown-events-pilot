# Devlog — краткий конспект

Короткая версия журнала для пересказа. Подробности, цифры и ссылки — в `docs/devlog.md`.

**Трек B — TypeScript:** мой опыт — JavaScript и TypeScript, а не .NET, поэтому на этом стеке я могу проверять, что делает агент, а не просто принимать результат.

---

**EXT-100 — задачи маршрута в GitHub Issues.** Через MCP агент завёл 11 задач трека B как issues, по порядку маршрута.
_Агент:_ сам заметил, что взял заголовки не из той таблицы, и исправил пять issues.
_Я:_ утвердил список заранее; метку `optional` создал руками — у MCP нет такой команды, обходить через консоль запретил.
_Урок:_ не нажимать «don't ask again» — дольше, но видно каждый шаг агента.

**BEVN-001 — карта кода.** Документ об устройстве бэкенда: схема базы, слои, эндпоинты, разбор запросов и список проблем — задел для аудита.
_Агент:_ при перепроверке нашёл свою ошибку — в ответы API утекал весь граф данных, включая email участников.
_Я:_ потребовал перепроверку; заметил, что диаграммы Mermaid не отображаются, — переделали в картинки.
_Урок:_ «проверь свою работу» находит ошибки по существу; фронтенд меняет выводы о бэкенде — смотреть сразу оба.

**BEVN-002 — документация API.** Все эндпоинты описаны в Swagger, поведение API не менялось. Каждый новый способ проверки находил ошибки, которые пропустил предыдущий.
_Агент:_ найденные баги записал как известные, а не стал чинить вне задачи.
_Я:_ попросил перечислить допущения — часть оказалась ошибками; устроил слепой тест: отдельный агент по одной документации ответил верно на все 13 вопросов.
_Урок:_ «задокументировано» не значит «верно»; каждое утверждение о поведении API — с проверочным запросом.

**BEVN-003 — аудит технического долга.** 54 находки с местом в коде, важностью и исправлением; главные подтверждены запросами на отдельном стенде.
_Агент:_ нашёл ошибку в своём скрипте замеров и переснял все цифры.
_Я:_ воспроизвёл главный дефект в браузере и опроверг прогноз агента; заказал слепой аудит — он подтвердил основное и добавил 3 находки.
_Урок:_ состояние процесса может прятать дефекты — замерять на чистом состоянии; прогноз агента тоже надо проверять.

**EXT-110 — CI на GitHub Actions.** Пайплайн проверяет бэкенд и фронтенд на каждый PR; старый GitLab-конфиг разобран и удалён.
_Агент:_ не поверил зелёному значку — нашёл в логе, что собирала не та версия .NET, и исправил.
_Я:_ попросил перепроверить план — нашлись три неточности; одно из допущений оказалось неверным.
_Урок:_ итог CI читать по логу, а не по значку; инструменты ставить до начала задачи.

**BEVN-101 — медленная страница сессий (N+1).** Вместо сотен SQL-запросов — один; страница на 100 сессиях: было 25 секунд и 1,26 ГБ, стало 0,3 секунды и 1 КБ.
_Агент:_ выбрал точечные запросы вместо глобального отключения ленивой загрузки; спорное выносил на моё решение.
_Я:_ выбрал критерий «данные не изменились»; проверил в Chrome; гонку оставил для миграции.
_Урок:_ критерий «ничего не сломали» выбирать до исправления; известные дефекты могут заблокировать проверку.

**EXT-150 — перенос бэкенда с .NET на TypeScript.** Бэкенд переписан на NestJS и Prisma с тем же API и базой; ответы сверены со старым — расхождений нет, дефекты аудита не воспроизводятся. Работа по spec и плану из 16 шагов.
_Агент:_ нашёл пустой тест гонки; один раз опасно ошибся — завершил все процессы Node разом, после этого правило «только свои процессы».
_Я:_ вёл вторую сессию Claude как ревьюера каждого шага; ввёл правило «сначала падающий тест, иначе — намеренная поломка».
_Урок:_ тест, который проходит до кода, ничего не доказывает; spec и план — дольше, но объём это оправдывает.

**BEVN-115 — модалка регистрации со старыми данными.** Баг в описанном виде не воспроизвёлся; настоящая проблема нашлась рядом — поздний ответ портил уже новую форму. Исправлено, во фронтенд добавлены первые тесты.
_Агент:_ проверку без задержки сети не засчитал — повторил с искусственно медленным ответом.
_Я:_ ограничил объём; добавил проверку намеренной поломкой, раз тесты были зелёными до исправления.
_Урок:_ баг может прятаться в соседнем сценарии.

**EXT-151 — Register у закрытых конференций и сырые ошибки.** (Хвост EXT-150: фронтенд не знал о новых ошибках API.) Для закрытых конференций регистрация скрыта, ошибки API показываются читаемым текстом.
_Агент:_ перед планом перепроверил факты запросами; остановился, когда две проверки упёрлись в одну причину.
_Я:_ выбрал надпись «Registration is closed» и формат ошибок; прошёл проверку в браузере.
_Урок:_ чистый `git status` не значит, что окончания строк не поменялись.

**BEVN-202 — список ожидания на сессию.** Когда мест нет, можно встать в очередь; при отмене место получает первый в очереди.
_Агент:_ предлагал одну сессию на участника — после моего вопроса «а если сессии идут подряд?» перешли на запись на каждую сессию.
_Я:_ принял бизнес-правила; заказал критика в свежей сессии — он нашёл, что новичок мог обогнать ждущего; выбрал «честный» вариант.
_Урок (мой итог):_ сверяться с агентом на каждом шаге и задавать самокритичные вопросы — каждый раз находилось пропущенное.

**BEVN-203 — дашборд регистраций.** Участник по email видит свои регистрации и может отменить подтверждённую; места уходят очереди.
_Агент:_ на пробе до кода выяснил, что миграция не откатывается целиком, и переписал её.
_Я:_ настоял на букве требований (кнопка отмены у каждой регистрации); решил не делать аутентификацию в пилоте; утечку email в лог из ревью попросил подтвердить на стенде.
_Урок (мой):_ планировать поэтапно, заранее уточнять требования, всё время сверять и подвергать сомнению.

**EXT-152 — обновление Vite и Vitest.** (Хвост BEVN-115: тесты на старом Vite принесли критическую уязвимость.) Инструменты фронтенда обновлены, критические уязвимости ушли.
_Агент:_ оставил две умеренные уязвимости вне задачи и объяснил, почему они к нам не применимы.
_Я:_ подтвердил версии и решение; прошёл проверку в браузере.
_Урок:_ обновление сборки тянет за собой образ — версию Node проверять до правок.

**BEVN-205 — e2e-тесты на Playwright.** Три сценария (обзор, запись на сессию, список ожидания) проверяются в браузере против всего приложения; в CI при падении сохраняется скриншот.
_Агент:_ каждый тест сначала намеренно ломал, чтобы убедиться, что он умеет падать.
_Я:_ перевёл тесты на TypeScript; находку ревьюера агент не воспроизвёл — я разобрал последствия и всё равно выбрал укрепить тест.
_Урок:_ зелёный тест ничего не доказывает, пока не видел его красным; замечание ревьюера сначала воспроизвести.

## Главное за пилот

- **Проверять, а не верить:** утверждения агента, ревьюера и свои прогнозы — подтверждать запросом, тестом или логом.
- **Перепроверка окупается:** вопросы «проверь себя» и «какие были допущения» почти всегда находили ошибку.
- **Тест доказывает что-то, только если его видели красным.**
- **Независимый взгляд** — слепые тесты, критик, ревьюер в свежей сессии — находил то, что пропускал основной агент.
- **Решения — за мной:** агент предлагал варианты с последствиями, ставил под вопрос, корректировались варианты пути, и принимал решение.
- **Опыт:** - очень полезный опыт работы с агентом, учет его возможностей, ограничений и нюансов работы с ним.
