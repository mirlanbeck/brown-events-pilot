# BEVN-001: Codebase mapping

## Что сделали и что получилось

Агент прочитал весь бэкенд (Program.cs, модели, AppDbContext, контроллеры, сервисы,
сидер, тесты) и написал `docs/architecture.md`: ER-диаграмму, таблицу слоёв,
таблицу эндпоинтов и три сквозных запроса (GET сессий конференции, POST регистрации,
PUT сессии). В конце документа есть раздел «Наблюдения»: найденные проблемы
без исправлений, задел для BEVN-003.

Затем было три итерации:

1. Самопроверка по моей просьбе. Агент нашёл у себя существенную неточность:
   ленивую загрузку он описал слишком узко. На деле при сериализации в любой ответ
   попадает весь граф объектов, включая email участников. Ещё он дописал стек,
   отсутствие [ApiController], расхождение тестов (InMemory) с продом и Swagger в Production.
2. Подробное объяснение с визуалами. Агент сделал интерактивную HTML-страницу:
   карта контейнеров, слои, запуск, ER и пошаговый разбор пяти операций.
   Для неё он дочитал фронтенд и нашёл новые факты, которые поменяли выводы о бэкенде:
   - nginx- и Vite-прокси не используются, api.js ходит прямо на :5000;
   - интерфейс получает спикера, зал и участников только через ленивую загрузку;
   - phone/company/sessionId из формы регистрации молча теряются, письма не отправляются;
   - страница конференции шлёт три параллельных запроса в один общий (Singleton) DbContext.
3. Схемы в репозитории. Mermaid в предпросмотре VS Code отображался как код,
   а не как диаграммы. Заменили его шестью SVG в `docs/diagrams/`
   (карта системы, слои, ER, три flow-схемы) с нумерованными пояснениями под каждой.

DoD сверил с issue #2 через gh: все 4 пункта закрыты.

## Решения агента

- Без моей подсказки агент добавил в документ раздел «Наблюдения» с проблемами кода,
  но сам код не трогал, потому что задача — только карта. Принял это действие потому, что данные по проблемам проинформируют последующие исправления багов и учет упущений в дальнейших задачах.
- После самопроверки исправил собственную формулировку про сериализацию,
  а позже ещё одну, про ответ регистрации: граф конференции попадает туда не всегда,
  а только если конференция уже загружена в контекст.
- Для визуализации предложил SVG вместо расширения для Mermaid, ASCII или ссылки
  на артефакт: только SVG видно везде, и в VS Code, и на GitHub.
  Отказался от mermaid-cli (тянет Chromium). Схемы сгенерировал скриптом
  и проверил рендером через headless Edge.

## Где вмешался руками

- Попросил перепроверить работу. Это дало реальные исправления, а не косметику.
- Заметил, что Mermaid-диаграммы в предпросмотре — просто текст.
  Агент предупреждал, что рендер не проверял, но сам этого не сделал.
- Попросил сверку с Definition of Done из issue.
- Для отображения диаграмм выбрал вариант с SVG из предложенных. Обычные изображения открываются в предпросмотре VS Code (Ctr + Shift + V), на GitHub и в браузере без расширений и остаётся чётким при любом масштабе.
